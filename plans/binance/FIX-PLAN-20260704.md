## 3. 详细修复方案

### A1: 修复 NATS subject 段数不匹配 (N2)

**问题**：publisher 生成 5 段 subject `binance.market.{pl}.{et}.v1`，consumer filter 为 4 段 `binance.market.*.*`。NATS `*` 匹配恰好 1 个 token，5 段 subject 不会命中 4 段 filter。

**修复**：将 consumer 默认 Subject 从 `binance.market.*.*` 改为 `binance.market.>`（`>` 匹配 1+ tokens）。

```go
// consumer.go:22
Subject = "binance.market.>"  // 原: "binance.market.*.*"
```

**风险**：`>` 通配范围更广，但本模块 subject 前缀 `binance.market.` 是专用的，无其他 stream 共享此前缀。

### A2: 接入 UM/CM/Options connector (N4)

**问题**：`runtime.go:314` 仅创建并启动 `NewSpotConnector`，UM/CM/Options connector 代码存在但未被调用。

**修复**：在 runtime.go 中为每个 product line 创建 connector，合并 events channel。

```go
// runtime.go ~314
type connectorEntry struct {
    connector client.Connector
    events    <-chan client.NormalizedEvent
}

var connectors []connectorEntry

// Spot
spotCfg := DefaultSpotConfigForMode(cfg.Mode)
spotCfg.StreamBase = cfg.StreamBase
if len(cfg.Streams) > 0 { spotCfg.Streams = cfg.Streams }
sc := NewSpotConnector(NewGorillaDialer(), catalog, spotCfg)
sev, _ := sc.Start(ctx)
connectors = append(connectors, connectorEntry{sc, sev})
defer func() { _ = sc.Stop(context.Background()) }()

// UM Perp（如果启用）
if cfg.EnableUMPerp {
    umCfg := DefaultSpotConfigForMode(cfg.Mode) // SpotConfig 复用
    umCfg.StreamBase = cfg.StreamBase
    uc := NewUMPerpConnector(NewGorillaDialer(), catalog, umCfg)
    uev, _ := uc.Start(ctx)
    connectors = append(connectors, connectorEntry{uc, uev})
    defer func() { _ = uc.Stop(context.Background()) }()
}

// CM Perp / Options 同理...

// 合并 events
events := mergeChannels(connectors)
```

**配置扩展**：在 `StandaloneConfig` 中增加 `EnableUMPerp`/`EnableCMPerp`/`EnableOptions` 布尔字段，默认 false（向后兼容），生产环境按需开启。

### A3: TaosWriter 支持 funding_rate/mark_price (N6)

**问题**：`taos_writer.go:217-226` 的 `toPoint()` 仅处理 trade/tick/bar，funding_rate 和 mark_price 返回 `ErrUnsupportedEventType`。

**修复**：新增两个 case 分支和对应的 point 构建方法。

```go
// toPoint() 新增
case "funding_rate":
    return w.fundingRatePoint(event)
case "mark_price":
    return w.markPricePoint(event)
```

**新增方法**：

- `fundingRatePoint()`: 写入 `st_funding_rate` 表，字段含 symbol/product_line/funding_rate/funding_time/mark_price
- `markPricePoint()`: 写入 `st_mark_price` 表，字段含 symbol/product_line/mark_price/index_price/funding_rate/event_time

**schema**：需要在 TDengine migrations 中创建对应 super table。

### A4: retention ProductLine 去硬编码 (N7)

**问题**：`storage.go:257` 硬编码 `ProductLine: "spot"`，导致 UM/CM/Options 的 retention 不执行。

**修复**：从配置读取 product lines 列表，为每个 product line 创建 retention scheduler。

```go
// storage.go ~253
productLines := []string{"spot", "um_perp", "cm_perp", "options"}
for _, pl := range productLines {
    for _, rcfg := range buildTaosRetentionConfigs(ctx, pgClient) {
        scheduler, err := newTaosRetentionScheduler(taosWriter, archiver, storage.TaosRetentionConfig{
            ProductLine: pl,  // 原: "spot"
            EventType: rcfg.eventType,
            // ...
        })
        // ...
    }
}
```

### A5: depth 完整档位存储 (ORDBK)

**问题**：depth 事件在 `normalize.go` 保留完整档位（`DepthBids`/`DepthAsks`），但 `taos_writer.go` 将 depth 映射为 tick，只写入 4 个标量字段。

**修复**：新增 `depthPoint()` 方法，写入完整档位到 `st_depth` 表。

```go
// toPoint() 新增
case "depth":
    return w.depthPoint(event)
```

**depthPoint()**：解析 `DepthFields`，将 bids/asks 数组序列化写入 `st_depth` 表。

**schema**：`st_depth` 表含 symbol/product_line/bids_json/asks_json/update_id/depth_level 字段。
