# Anti-Requirements: FoundationX

> 全局反需求 — AI 代理和人类贡献者在所有模块中**不应该做的事**。

最后更新：2026-06-07
Status: Approved

---

## 1. 目的

本文档定义 FoundationX 项目中全局禁止的行为。这些规则适用于所有模块，无论其 spec 中是否有单独说明。

违反反需求的代码变更**必须被阻塞**，不得合并。

---

## 2. 禁止事项

### 2.1 依赖管理

| 禁止 | 原因 | 替代方案 |
|------|------|----------|
| 引入未经批准的依赖 | 违反 spec 的依赖约束，增加供应链风险 | 在 spec 中明确列出依赖，获得人工审批 |
| 引入已知有安全漏洞的依赖 | 安全风险 | 使用 `govulncheck` 检查，升级或替换 |
| 在 L0 模块引入非 stdlib 依赖 | 违反 kernel 的 stdlib-only 原则 | 将功能移到更高层级模块 |
| 循环依赖 | 违反依赖方向原则 | 通过 contracts 接口解耦 |

### 2.2 进程控制

| 禁止 | 原因 | 替代方案 |
|------|------|----------|
| 在库中使用 `log.Fatal` | 库不应决定进程退出 | 返回错误，由调用方决定如何处理 |
| 在库中使用 `os.Exit` | 库不应决定进程退出 | 返回错误，由调用方决定如何处理 |
| 在非测试代码中使用 `panic` | 违反错误处理原则，可能导致级联故障 | 返回错误 |
| 在库中使用 `init()` 做副作用操作 | 初始化顺序不可控，难以测试 | 使用显式初始化函数 |

### 2.3 配置管理

| 禁止 | 原因 | 替代方案 |
|------|------|----------|
| 硬编码配置值 | 违反配置管理原则，不同环境需要不同值 | 通过 configx 读取配置 |
| 硬编码端口、地址、URL | 不同环境需要不同值 | 通过配置注入 |
| 硬编码超时值 | 不同场景需要不同超时 | 通过配置或 Option 模式注入 |

### 2.4 安全

| 禁止 | 原因 | 替代方案 |
|------|------|----------|
| 硬编码 secret、API key、密码 | 泄露风险，违反安全原则 | 使用环境变量或密钥管理器 |
| 在日志中记录敏感数据 | 泄露风险 | 使用 `SecretString` 脱敏 |
| 在错误消息中泄露配置细节 | 信息泄露 | 错误消息只包含模块名和错误类型 |
| 使用 `unsafe` 包 | 绕过 Go 的内存安全保证 | 除非有充分理由并记录在 spec 中 |
| 跳过输入校验 | 安全风险 | 在系统边界处校验所有外部输入 |

### 2.5 架构

| 禁止 | 原因 | 替代方案 |
|------|------|----------|
| 跨域直接调用（不通过 contracts） | 违反模块解耦原则 | 通过 `contracts` 包的接口通信 |
| 数据职责跨域 | 违反数据域边界 | 每个数据域有明确的所有者模块 |
| 在 x.go 中写业务逻辑 | 违反组合根原则 | 业务逻辑放在对应的业务域模块 |
| 修改 CONSTITUTION.md 未经审批 | 宪法变更需要人工审批 | 提交 PR，等待人工 review 和批准 |
| 策略直接提交订单（绕过 risk-engine） | 违反风控原则 | 所有订单必须通过 risk-engine 审批 |

### 2.6 测试

| 禁止 | 原因 | 替代方案 |
|------|------|----------|
| 跳过测试 | 测试是验收的唯一证据 | 每个行为变更必须有对应测试 |
| 在测试中硬编码敏感数据 | 泄露风险 | 使用合成数据或脱敏数据 |
| 测试依赖外部服务 | 测试不稳定，不可重复 | 使用接口 mock 或 testdata |
| 修改代码后不更新测试 | 测试失效，无法保证正确性 | 同步更新测试 |

### 2.7 代码质量

| 禁止 | 原因 | 替代方案 |
|------|------|----------|
| 静默吞掉错误 | 违反错误处理原则，问题难以排查 | 显式处理或传播错误 |
| 函数超过 50 行 | 可读性差，职责不单一 | 拆分为更小的函数 |
| 文件超过 800 行 | 职责过多，难以维护 | 提取模块 |
| 嵌套超过 4 层 | 可读性差 | 使用提前返回重构 |
| 使用魔法数字 | 含义不明 | 使用命名常量 |
| 修改无关文件 | 保持变更范围最小 | 只修改相关的文件 |

## 3. 审查检查清单

在代码审查时，逐项检查以下禁止事项：

- [ ] 无未经批准的新依赖
- [ ] 库代码无 `log.Fatal` / `os.Exit` / `panic`
- [ ] 无硬编码配置值（端口、地址、超时、密钥）
- [ ] 无硬编码 secret / API key / 密码
- [ ] 敏感数据不写入日志
- [ ] 跨域调用通过 contracts 接口
- [ ] 数据职责不跨域
- [ ] x.go 无业务逻辑
- [ ] CONSTITUTION.md 未被修改（除非有审批）
- [ ] 所有行为变更有对应测试
- [ ] 测试不依赖外部服务
- [ ] 错误被显式处理，不静默吞掉
