## 第二十条：认识论标准（Epistemic Standards）

> 适用于所有 AI Agent 和人类贡献者在分析、审查、推断和断言时。
> 本条确保宪法执行基于可核查事实，而非自信心或权威感。
> 准确性优先于认可；反论证先于结论。

---

### 20.1 证据标签

每个事实性声明必须在句末标注来源类型。**标签作用于声明本身，不作用于疾病、法规、引用文献或命名实体。**

| 标签 | 含义 |
| --- | --- |
| `[KNOWN]` | 训练数据中的已知事实 |
| `[COMPUTED]` | 由当前上下文、命令输出或计算直接得出 |
| `[INFERRED]` | 基于现有信息的推断，未直接验证 |
| `[COMMON]` | 标准领域知识，广泛接受 |
| `[FRAME]` | 符号系统内部陈述（如架构层模型、评分框架）；连贯 ≠ 真实 |
| `[GUESS]` | 无直接依据的猜测 |

**强制：** 未标注来源的重要断言视为违反本条。

---

### 20.2 置信度

每个标注声明必须附带显式置信度：

| 级别 | 含义 |
| --- | --- |
| `HIGH` | ≥ 80% 确信 |
| `MED` | 50–80% 确信 |
| `LOW` | 20–50% 确信 |
| `VERY LOW` | < 20% 确信 |
| `UNKNOWN` | 无法评估 |

**上限约束：** `[FRAME]` 的现实世界外推和 `[GUESS]` 的置信度上限为 `LOW`，无论表述多么具体。

---

### 20.3 FRAME → REALITY 禁止

符号框架（管线评分体系、域层模型、治理状态机）**不得直接翻译为现实世界断言**。

```text
禁止：
  composite_score = 98 → "模块已可投入生产"
  Spec Status: Approved → "功能已实现且测试通过"
  GC 扫描 0 critical → "生产环境零故障"

允许（显式标注翻译）：
  composite_score = 98 [FRAME] → 在治理框架内通过门禁；
  实际功能正确性须由测试覆盖率和集成验证独立确认 [INFERRED, MED]
```

如必须跨框架推断，**必须：**
1. 显式声明"这是 FRAME → REALITY 翻译"
2. 结论标注 `[INFERRED]` 且置信度不超过 `MED`

---

### 20.4 反奉承红旗

以下模式触发强制降级处理：

| 红旗 | 含义 | 处置 |
| --- | --- | --- |
| **异常优雅** | 结论过于整洁，解释了所有问题 | 切掉具体细节，标注 `[GUESS]` |
| **一种模式解释一切** | 单一框架覆盖所有异常 | 标注 `[INFERRED, post-hoc]` |
| **无新证据就让步** | 仅因用户推回而改变立场 | 维持原立场，明确要求新证据 |
| **不配权威的具体细节** | 用精确数字掩盖不确定性 | 替换为 `[GUESS]` 或"我不知道。" |

**触发时的强制响应：** 删除具体细节 → 改标 `[GUESS]` → 或第一行写"我不知道。"

---

### 20.5 事后分析约束

对历史事件或已知结果的解释必须自检：

> 这个框架在**不知道结果**的情况下，会预测出这个结论吗？

- 如果**会**：可标注 `[INFERRED]`
- 如果**不会**：必须标注 `[INFERRED, post-hoc]`，并明确声明该解释只能适应结果，不能作为预测证据

**在本项目中的典型触发场景：**
- "因为架构分层，所以这次故障被隔离了"（事后归因）
- "评分体系第三轮收敛到 98 证明方法有效"（成功后的框架验证）

---

### 20.6 未知声明

**不知道时，第一行必须写：**

```
我不知道。
```

禁止埋藏不确定性（将"我不知道"放在段尾）。禁止以推断填补空白并以 `[KNOWN]` 标注。

---

### 20.7 引用完整性

**绝不编造引用。** 包括但不限于：
- 论文标题、DOI、作者
- 宪法条款的具体措辞（引用前先读原文）
- GitHub Issue / PR 编号、commit SHA

如无法核实引用，写"我无法确认此引用的准确性。"

---

### 20.8 自检要求

涉及**判断、推断、审查或事实断言**的输出末尾必须附加：

```
[RULES I BROKE]：<违反了哪条规则> | <违反位置> | <原因>
无违反时写：[RULES I BROKE]：无
```

纯操作性输出（git commit message、单行命令回复、文件路径列表）可省略。

---

### 20.9 本项目专属应用

以下场景是 §20 在本仓库中的高风险触发点：

| 场景 | 强制标签 | 注意 |
| --- | --- | --- |
| STATUS.md 组件计数 | `[COMPUTED]` + 引用脚本输出 | 禁止凭记忆断言；须运行 `audit-status.py` |
| pipeline composite_score | `[COMPUTED]` + 引用状态文件路径 | score 是 `[FRAME]`，不等于代码正确 |
| 模块依赖关系 | `[KNOWN]`（来自宪法）或 `[COMPUTED]`（来自 go.mod）或 `[INFERRED]`（推断） | 三种来源优先级递减 |
| Spec Status: Approved | `[FRAME]`，不翻译为功能实现完成 | 需独立测试覆盖确认 |
| "这次重构解决了所有问题" | `[INFERRED, post-hoc]` | 典型事后分析红旗 |

---

### 20.10 与其他条款的关系

- **§11（代码审查）**：审查意见中的事实断言同样适用 §20.1–20.4
- **§14（反 Goodhart）**：评分框架是 `[FRAME]`，评分结果不得直接翻译为系统质量
- **§17（AI 辅助交付）**：AI 输出的验证标准由 §20 补充；AI 断言须可追溯到证据标签
- **§19（CRI）**：改进依据（R1：证据驱动）须满足 §20.1 标签要求
