## 问题 1：SPEC.md 体量失控（严重度：HIGH）

**现状**：2075 行、100KB、52 个 FR 每个带 2 组 WHEN/THEN + 来源注释。

**合理范围**：按 23 节模板，一个模块 spec 应在 500-800 行。

**根因**：52 个 FR 全部内联，每个 FR 占 8-10 行（标题 + 2 WHEN/THEN + 来源），仅 FR 部分就约 450 行。加上 5 个参考资料附录（C/D/E 约 180 行）、膨胀的状态说明（33 行时间线），总量不可控。

**建议**：
>
- FR 细节拆到 `specs/xlib-standard/FR-DETAIL.md`，SPEC.md 只保留 FR 摘要表
- 参考资料 C/E 拆到独立文件或删除（信息与主规格重叠）
- 状态说明收敛为当前状态 + 一个链接指向变更日志

---

## 问题 2：状态说明变成变更日志（严重度：HIGH）

**现状**：SPEC.md:12-34 是 7 条带时间戳的增量更新（`2026-06-08 04:59`、`05:03`、`05:11`、`05:14`、`05:15`、`05:16`），共 23 行。

**问题**：状态说明应该是"当前是什么状态"，不是"怎么到达这个状态的"。7 条增量更新读起来像 git log，不是 spec。

**建议**：收敛为：

```markdown
> Status: Review（待独立 reviewer 签字后升级 Approved）
> Approved 前置条件：(1) 独立 reviewer 签字 ✅待补 (2) 远端治理证据 ✅已闭合 (3) 行级覆盖 100% ✅已达成
> 详细变更记录：见 CHANGELOG.md 或 git log
```

## 问题 4：TRACEABILITY.md 名不副实（严重度：MEDIUM）

**README.md 声明**："FR→AC→TC→实现 的追溯表"

**实际内容**：是"SPEC.md 条款到来源文件的追溯表（章节级，非 rule 级）"。FR 级追溯表（§"FR 级追溯"）只追溯到上游源文件行号，没有 AC→TC 映射。

>
**问题**：
>
- 没有 AC 编号表
- 没有 TC 编号表
- 没有 FR→AC→TC 闭合校验
- 名为"追溯矩阵"，实为"来源映射"

**建议**：要么重命名为 `SOURCE-TRACEABILITY.md`，要么补齐 FR→AC→TC 三列映射。

---

## 问题 5：CONFLICT-LEDGER 与 SPEC 信息冗余（严重度：MEDIUM）

**现状**：CONFLICT-LEDGER.md 的 22 项冲突，每一项的 `Resolved-in: SPEC.md §X.Y` 引用已在 SPEC.md 对应 FR 或节中内联说明。

**问题**：冲突的"取舍"信息在两个文件中各写了一遍。维护时必须同步更新两处。

**建议**：CONFLICT-LEDGER 保留冲突描述和取舍结论，SPEC.md 只引用 `CONFLICT-LEDGER #N`，不在 FR 中重复解释。

---

## 问题 6：COVERAGE-MANIFEST.md 绝对路径（严重度：MEDIUM）

**现状**：154 个文件清单使用占位符 `<upstream:xlib-standard>/...`，但复算命令仍含 `/home/xlib-standard` 绝对路径（L33-38）。

**问题**：其他 reviewer 无法直接复算。README.md 也承认"跨机器复现仍需要 source pack、路径映射或重新生成覆盖清单"。

**建议**：复算命令改为纯占位符形式，或提供 `generate-coverage.sh` 脚本。

## 问题 9：archive/ 目录增加认知负担（严重度：LOW）

**现状**：`archive/DEEP-ANALYSIS.md`（538 行）和 `archive/MODULE-SPEC.md`（450 行）是已归档的历史工件。

**问题**：即使标注了"不得作为当前规格引用"，它们仍在目录中占位，增加心智负担。新读者会困惑"该看哪个"。

**建议**：要么移到 `specs/xlib-standard-archive/` 顶层目录，要么删除（git history 已保存）。

---

## 问题 10：文件职责边界模糊（严重度：MEDIUM）

**6 个文件的职责重叠：**

```text
README.md          ← 索引 + 阅读规则 + 交付边界 + 覆盖口径（4 种职责）
SPEC.md            ← 主规格 + 附录 A-E + 状态变更日志（2 种职责）
TRACEABILITY.md    ← 来源追溯（不是 FR→AC→TC 追溯）
CONFLICT-LEDGER.md ← 冲突取舍（与 SPEC 重复）
COVERAGE-MANIFEST.md ← 文件清单 + sha256 + pinning procedure
REMOTE-EVIDENCE.md ← 远端治理证据（独立且清晰）
```

**唯一职责清晰的是 REMOTE-EVIDENCE.md**。
