### H-3：docs/report/ 目录污染 🟠 ✅ 已修复（2026-06-21 `df88600a`）

`docs/report/` 是文档目录，但其中存在工程文件：

```
docs/report/
├── package.json        ← npm 项目文件（不应在此）
├── package-lock.json   ← npm 锁文件（不应在此）
└── node_modules/       ← npm 依赖目录（内含分析文档残留）
    ├── codex-chatgpt-control/
    ├── xlib-standard-archive-readme.md
    ├── xlib-standard-*.md（多份存档报告）
    ├── ISSUE-LEDGER.md
    └── goal-docs-*.md（多份分析）
```

`node_modules/` 内部实际是伪装成 npm 包的历史分析文档（而非真正的 npm 包）。这带来：

1. 语义混乱：文档目录看起来像前端项目
2. `git status` 或 `grep` 工具可能意外扫描 node_modules
3. `.gitignore` 如果排除 node_modules 会导致这些历史文档丢失

**建议**：将 `node_modules/` 下的文档移至 `docs/report/archive/xlib_standard/` 等规范目录，删除 package.json/package-lock.json。

### M-3：管线评分 pass-through 导致信息失真 🟡

STATUS.md 管线状态表脚注明确说明：

> `pln/prm/cod 外仓模块为 pass-through，100 分仅表示文档模板完整，不代表代码可编译或已通过测试。`

但基座 20 个模块的明细表全部显示 `prm=100 cod=100`，读者很容易误解为"代码已实现并测试通过"。

**受影响的已知 pass-through 模块**（外仓，代码在独立 GitHub 仓库）：

- redisx、kafkax、natsx、postgresx、taosx、ossx、clickhousex
- contracts、transportx 等所有基座存储/中间件模块

这些模块的 `cod=100` 实际上只代表"此仓库的 Prompt 文档已按模板填写"，不代表 `/home/{module}/` 下的代码已验证。

**建议**：在明细表版本号或进度列旁增加标注 `[P]`（pass-through），或在列头说明"cod/prm 对外仓模块为文档模板评分"。
