# RSI 改进规格：文档清理（CONSTITUTION 渲染修复 + 治理备份规范化）

- **日期**: 2026-06-19
- **来源**: worktree 流程深度分析（§13.1 代码块闭合检查、branch-governance-backups 结构核查）
- **影响文件**: `CONSTITUTION.md` L618（§14.1 受保护，但属零语义笔误修复）、`docs/governance/BRANCH-GOVERNANCE-BACKUPS.md`（新增，非受保护）
- **状态**: 提议

---

## 问题与理想状态

**问题**：深度分析发现两处文档缺陷：

1. **CONSTITUTION.md §13.1 代码块未正确闭合**：第 606 行 `` ```text `` 正确开启代码块，但第 618 行应为闭合标记 `` ``` `` 却误写成 `` ```text ``（重复了开标记的 info string）。实测证据（精确行号）：

   ```
   606: ```text          ← 正确开启
   607: 本宪法 (CONSTITUTION.md)
   ...
   617: 其他文档
   618: ```text          ← BUG：应为 ```（闭合标记误写成开标记）
   619: (空行)
   620: ### 13.2 适用范围 ← 被错误吞进代码块渲染
   ```

   后果：因 `` ```text `` 不是合法闭合 fence，渲染器会认为代码块一直延续，导致 §13.2 标题、列表及后续内容（直到遇到下一个合法 `` ``` ``）被错误地吞进代码块。这是纯渲染 bug，**零语义变更**。

2. **`branch-governance-backups` 无文档且命名格式混乱**：`.git/branch-governance-backups/` 下 22 个时间戳目录使用 3 种格式混用：
   - `20260615T014035Z`（ISO 8601 UTC，带 Z）
   - `20260615-0926`（本地时间，连字符 HHMM）
   - `20260618T154655+0800`（ISO 8601 带时区偏移）

   且仓库内**无任何文档**说明这些备份的触发条件、归属（由仓库外治理 runner 产生，见 `runner-config-*`/`runner-disableupdate-*` 目录名）、保留策略。`grep` 全仓未找到声明产生这些备份的脚本/agent，对新人完全不透明。

**理想状态**：

1. §13.1 代码块正确闭合，§13.2 及后续内容正常渲染。
2. 治理备份有文档说明其用途、归属、保留策略，未来新备份遵循统一时间戳格式。

## 不做什么

- **不重命名现有 22 个备份目录**——它们是历史快照（含 `staged.patch`/`stash-*`/`refs.txt` 等治理操作前状态），重命名有破坏追溯链的风险且无实质收益。仅文档化规范供未来遵循。
- **不修 CONSTITUTION.md 语义内容**——ISC-1 仅闭合代码块（删 1 个 `text` 单词），不改效力层级、不增减条款。
- **不接入新的备份采集机制**——备份由仓库外 runner 产生，本提案仅做文档化，不改变其产生方式。
- **不清理（删除）旧备份目录**——保留策略由文档定义，本提案不执行删除。

## 约束

- `CONSTITUTION.md`（§14.1 受保护文件）：ISC-1 是零语义笔误修复，参照 `20260614-spec-ref-substance-over-form` 先例（该先例「措辞解释性修正，非算法性变化」获人类批准合并），走 §19 CRI R3（最低风险，可自动审批）。
- `docs/governance/BRANCH-GOVERNANCE-BACKUPS.md`（新增文档，非受保护）：§19 CRI R3。
- **§14 归属说明**：CONSTITUTION.md 虽在 §14.1 清单，但 L618 修复不改变任何条款语义（效力层级文本逐字不变，仅闭合 fence）。按 §14.6「§14.2 至 §14.5 条款只能由第十二条修正程序修改」，本修复不触及 §14.2–14.5，且效力层级（§13.1）本身的内容未变，故不触发 §14.3 五步 RSI。**此判定若人类维护者认为应走 §14.3，则升级。**
