# 治理操作前分支备份（branch-governance-backups）

- **文档定位**: 说明 `.git/branch-governance-backups/` 目录的用途、归属、保留策略与命名规范
- **状态**: 参考性文档（非受保护）
- **创建日期**: 2026-06-19
- **来源**: worktree 流程深度分析（RSI `20260619-docs-cleanup`）

---

## 1. 用途

`.git/branch-governance-backups/` 下的每个时间戳子目录，是**某次治理操作执行前**对本地 Git 工作状态的快照，用于在治理操作（强制切回 main、强制 rebase、清理分支等）破坏既有状态时提供回滚入口。

典型快照内容（以实际目录为准）：

- `refs.txt` —— 当时的本地分支与 ref 列表
- `staged.patch` —— 暂存区差异（未提交改动的 patch）
- `stash-*` —— `git stash` 产生的 stash 记录引用
- `worktree` 相关状态 —— 被治理操作触及的 worktree 元信息

这些快照不是 git 原生产物，也不是仓库版本历史的一部分，而是治理操作为「可回滚」预留的安全网。

## 2. 归属

**这些备份由仓库外的治理 runner 产生，不是仓库内脚本或 agent 产生的。**

证据线索：

- 目录名形如 `runner-config-*` / `runner-disableupdate-*`，前缀表明由外部 runner（运行在仓库之外的治理执行器）写入
- 仓库内 `grep` 未找到任何声明产生这些备份的脚本或 agent（无 `.claude/hooks/*`、无 `scripts/*`、无 agent 定义引用 `branch-governance-backups`）
- 备份落盘时机是治理操作执行前，而治理操作的调度方位于仓库外部

因此：

- **不要在本仓库内新增脚本去产生或清理这些备份**——那会与外部 runner 的产生方产生双写冲突
- **理解这些目录的来源是外部 runner**，本仓库仅文档化其语义，不接管其产生/清理职责

## 3. 保留策略

由于备份由外部 runner 产生，保留策略的建议对象是**外部 runner 的维护者**，本仓库不作强制：

- **建议保留窗口**: 7–14 天。超过此窗口的快照，其回滚价值通常已被后续治理操作覆盖
- **清理责任方**: 外部 runner（按其自有 GC 策略执行），本仓库不主动删除
- **历史快照保护**: 现存历史目录应视为只读归档，重命名或删除会破坏追溯链（见 §4）

若外部 runner 暂无 GC，可接受备份目录无限累积——它们位于 `.git/` 下，不进版本库，不影响仓库体积。

## 4. 命名规范（未来新备份）

### 4.1 现状：三种格式混用

现存 22 个历史目录使用三种时间戳格式：

| 格式 | 示例 | 说明 |
|------|------|------|
| ISO 8601 UTC 带 Z | `20260615T014035Z` | UTC 时间 |
| 本地时间连字符 | `20260615-0926` | 本地时区，`-` 分隔 HHMM |
| ISO 8601 带时区偏移 | `20260618T154655+0800` | 带时区偏移 |

### 4.2 不重命名历史目录

**本规范明确声明：不重命名现有 22 个历史目录，仅规范未来新备份。**

理由：

- 历史目录是治理操作发生时的真实快照，其时间戳格式记录了当时 runner 的行为
- 重命名有破坏追溯链的风险（外部 runner 可能按原名引用）
- 统一历史命名无实质收益——这些目录只读归档，不会被程序消费
- 强制重命名会引入「为了一致性而改动历史」的反模式

### 4.3 未来新备份的推荐格式

**建议未来新备份统一采用 ISO 8601 带时区格式：**

```
YYYYMMDDTHHMMSS±HHMM
```

示例：

- `20260619T143000+0800` —— 2026-06-19 14:30:00 UTC+8
- `20260619T063000+0000` —— 2026-06-19 06:30:00 UTC

选择带时区而非纯 UTC（`Z`）的理由：治理操作通常由人类维护者在本地时间触发，带时区偏移的时间戳可直接读出本地时间，无需心算时差；同时 ISO 8601 保证全局可排序与机器可解析。

此建议对**外部 runner** 提出，本仓库不强制其采纳；若 runner 维护者评估后保留现状，亦可接受——备份语义不受命名格式影响。

## 5. 与仓库其他机制的关系

| 机制 | 关系 |
|------|------|
| `.worktree/` 孤儿 GC（`SessionStart` hook） | 不同职责：worktree GC 清理 worktree 目录残骸；本备份是治理操作前的状态快照，两者不重叠 |
| `git reflog` | 互补：reflog 记录 HEAD/分支移动，备份额外保存暂存区/stash/worktree 状态，覆盖 reflog 不记录的部分 |
| `git stash` | 备份内 `stash-*` 引用的是 stash 产生的记录，备份本身不产生 stash |
