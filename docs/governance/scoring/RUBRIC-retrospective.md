# Retrospective 评分 Rubric

> 评分对象：复盘报告、Patch 计划、改进项跟踪
> 总分：100。

## 维度（满分 100）

| 维度          | 满分   | 检查重点                                     |
| ------------- | ------ | -------------------------------------------- |
| Goal 达成评估 | 18     | Goal 定义的成功指标是否达成，差距量化        |
| 过程回顾      | 15     | 管线各阶段耗时、瓶颈、阻塞项已记录           |
| 根因分析      | 15     | 未达标项的根因已分析，非表面归因             |
| 改进项具体    | 13     | 改进项有明确的 Action Item、Owner、截止日期  |
| 经验沉淀      | 12     | 可复用的经验已提取为规则或模板改进           |
| 数据驱动      | 10     | 复盘结论有数据支撑（耗时、缺陷数、覆盖率等） |
| Patch 计划    | 10     | 遗留问题有后续 Patch 计划和跟踪 ID           |
| 知识传播      | 7      | 复盘结论已同步到相关文档或团队               |

## 阶段特定红线

- Goal 达成情况未评估。
- 改进项无 Owner 或截止日期。
- 存在遗留问题未创建跟踪 ID。
- 复盘结论纯主观，无数据支撑。

## 通过门禁

Goal 达成已评估、改进项已分配、遗留问题已跟踪 → 标记 DONE。
