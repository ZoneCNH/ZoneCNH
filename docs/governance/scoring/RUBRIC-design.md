# Design 评分 Rubric

> 评分对象：`module/{module}/DESIGN.md` 或等效设计文档
> 总分：100。

## 维度（满分 100）

| 维度           | 满分   | 检查重点                                         |
| -------------- | ------ | ------------------------------------------------ |
| 架构方案清晰   | 15     | 组件划分、职责边界、交互方式有明确描述           |
| 与 Spec 对齐   | 15     | 设计覆盖 Spec 中所有 FR/BR，无遗漏或越界         |
| 接口定义完整   | 13     | 对外接口签名、输入输出、错误码已定义             |
| 数据模型设计   | 12     | 核心实体、关系、状态变迁有定义                   |
| 依赖与约束     | 10     | 上下游依赖明确，技术约束（性能/安全/合规）已标注 |
| 可测试性       | 10     | 设计支持单元测试和集成测试，mock 点明确          |
| 风险与替代方案 | 13     | 高风险点已识别，备选方案已评估并记录决策理由     |
| 可扩展性与演进 | 12     | 未来扩展路径清晰，当前设计不阻塞已知演进方向     |

## 阶段特定红线

- 设计未覆盖 Spec 中任一 FR。
- 核心接口未定义签名。
- 高风险决策无替代方案记录。
- 设计引入 Spec 明确排除的技术方案。
- 数据模型存在循环依赖或未定义的实体关系。

## 通过门禁

`composite_score = min(四源评分)` 且 `composite_score >= 98`、无红线、无 LLM 低置信度、LLM 分差与 rules 异构分歧在阈值内 → 进入 Plan 阶段。
