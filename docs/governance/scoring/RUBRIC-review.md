# Review 评分 Rubric

> 评分对象：Review 结论、Checklist 审查结果、Goal/Spec 回溯验证
> 总分：100。

## 维度（满分 100）

| 维度             | 满分   | 检查重点                                  |
| ---------------- | ------ | ----------------------------------------- |
| Goal 回溯验证    | 15     | 实现是否达成了 Goal 定义的成功标准        |
| Spec 覆盖验证    | 15     | 所有 FR/BR 是否被实现且有测试覆盖         |
| 设计一致性       | 12     | 实现是否遵循 DESIGN.md 的架构方案         |
| 代码质量审查     | 13     | 代码可读性、可维护性、命名规范            |
| 安全审查         | 12     | 无硬编码密钥、输入校验、权限控制          |
| 性能审查         | 10     | 无 N+1 查询、无不必要的内存分配、满足 NFR |
| 变更影响评估     | 13     | 对现有功能的影响已评估，无意外破坏        |
| Checklist 完整性 | 10     | 所有审查项已逐条检查并记录结论            |

## 阶段特定红线

- 存在 CRITICAL 或 HIGH 级别问题未修复。
- 安全审查未执行。
- 变更影响未评估。
- Review 结论与测试结果矛盾（如 Review PASS 但测试 FAIL）。

## 通过门禁

无 CRITICAL/HIGH 问题、安全审查通过、变更影响已评估、Checklist 完整 → 进入 Release 阶段。
