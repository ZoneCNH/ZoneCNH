# ADR-004: 有版本号统计包含 v0.1.0-draft

> 状态：Accepted
> 日期：2026-06-15
> 决策者：ZoneCNH (audit session)
> 关联：PR #391; STATUS.md 按域统计表 有版本号 列

---

## 背景

2026-06-15 审计发现按域统计表"有版本号"列存在遗漏——分析域、决策域、执行域被标为 1/0/0，但实际有 7 个 v0.1.0-draft 模块（flowx, backtestx, strategyx, maestro, riskx, orderx, positionx）在组件表中明确拥有非空、非 `-` 的版本号字符串。

计数偏差的根因：agent 凭直觉将 `-draft` 后缀排除在"正式版本"之外，但未认识到排除后"有版本号 + 无版本号 ≠ 总数"，导致合计行自洽恒等式断裂。

---

## 决策

**`有版本号` 包含所有在组件表版本列中有明确、非空、非 `-` 字符串的模块，包括 `v0.1.0-draft`。**

---

## 替代方案

### 方案 A：仅计入有 git tag 的版本

排除 `-draft` 和 `-spec` 后缀。

- 未选择原因：STATUS 组件表的版本列承载的是"描述性版本状态"，而非严格的 git tag 镜像。`-draft` 表示 SPEC 已创建但未正式发布，与 `-`（完全无版本）是不同的状态层。排除它们会丢失信息，且破坏了"有版本号 + 无版本号 = 总数"的恒等式。

---

## 后果

### 正面

- 域统计恒等式闭合：37 + 43 = 80
- 审计自动化：`awk -F'|'` 逐行提取版本列，非空且非 `-` 即计入，规则确定无歧义
- 三个域（分析域/决策域/执行域）的进度可见性提升

### 负面影响

- "有版本号"的语义不再等同于"已发布"——`v0.1.0-draft` 模块没有 git tag 也没有 Release
- 读者可能误将 37 解读为"37 个模块已发布"

### 风险

| 风险 | 概率 | 影响 | 缓解 |
|------|:---:|:---:|------|
| 读者误解"有版本号"含义 | 中 | 低：不影响数据正确性 | 列名可改为"有版本字符串"（后续 PR） |
| 未来 draft 模块 release 后计数重复 | 低 | 低：版本号从 draft 变为正式版，总数不变 |

---

## 约束

- 不改变组件表版本列的实际值
- 不影响 RELEASE 维度的判断（版本字符串存在 ≠ 有 GitHub Release）
